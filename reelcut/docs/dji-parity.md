# DJI Studio와 Reelcut 비교표

기준: DJI Studio 1.2.25 설치 파일에서 읽은 내용과 실제 Osmo 360 II 영상(`CAM_20261025164144_0007_D.OSV`, 29.97fps) 측정값. DJI 파일은 읽기만 했고 실행하지 않았습니다. Reelcut에는 DJI 코드와 모델이 들어 있지 않습니다.

어디서 읽었는지:
- `VinceEditor.dll`: 그대로 읽힘. 메타데이터 protobuf 정의, EIS 함수 호출 방식
- `stitch_with_sym.dll`: 그대로 읽힘. 심볼과 GLSL 셰이더 207개
- `dual_fisheye_video_eis_win.dll`: VMProtect로 싸여 있어(`.text` 비어 있음, `.vmp2` 엔트로피 7.1) 코드를 읽지 못함. 실행해서 푸는 일은 하지 않음

## 바꾼 것

| 기능 | DJI 방식과 찾은 곳 | Reelcut 이전 | Reelcut 이후 | 측정 결과 |
|---|---|---|---|---|
| 렌즈 왜곡 | 파일의 `DewarpParams`(fx, fy, cx, cy, k1~k9, 정의: VinceEditor.dll). 이 파일에는 k1~k5 값이 있음 | r = f·θ 직선, 화각 193.4° | r = fx·θ(1+k₁θ²+…+k₅θ¹⁰)로 내보내기와 미리보기 모두 계산 | 렌즈 중심 부근 배율 차이 약 8% 해소(1137 → 1053 px/rad) |
| 렌즈 중심 | 같은 값(`cx`, `cy`) | 그림 가운데로 가정 | 파일 값 사용 | 앞 렌즈 x 중심 7.5px 차이(3840 기준) 해소 |
| 두 렌즈 각도 | `cam_extri_q` | 화면을 보고 탐색(0.85, 0.15, −0.45) | 파일 값(−0.09, 0.14, −0.32) | 프레임에 맞춘 탐색값과 평균 거의 같음. 아래 참고 |
| 미리보기 스티칭 | 그래픽 칩에서 렌즈를 바로 이음(`AiStitchOpenglImpl`, 렌더러) | ffmpeg `v360`으로 구를 만들어 전송 | 두 렌즈를 그대로 보내고 셰이더가 내보내기와 같은 식으로 이음 | 미리보기-내보내기 이음새 PSNR(절반 크기) 40.8~47.6 → 42.4~49.7dB, 밝기 차 0.45 → 0.09 이내. 실제 셰이더가 아니라 같은 식을 옮긴 Rust 코드로 잰 값 |
| 자세 값 | `IMU_attitude_after_fusion`(프레임당 33~34개, 정의: VinceEditor.dll) | 같음 | 같음. 시각이 어긋난 패킷을 버리고, 시간차를 1ms 단위로 맞춤 | 19.25초 전 값이 든 패킷 1개 제거 |
| 프레임 동기 | `PanoEisRenderer::getMatrixForEisAndHorizontal(frameIndex)`: 프레임 번호로 행렬을 구함 | 재생기 시계로 프레임을 고름(항상 1프레임 어긋남) | 스트림에 프레임 번호를 넣어 그림에서 읽음 | 흔들림 보정 떨림 295초 3.06~3.20 → 0.47, 420초 2.22~2.27 → 0.40 |
| 수평만 맞추기 | `isUseHorizonCorrect`, `EisGetMatrixForTiltRecovery`로 안정화와 별도 항목임을 확인 | 안정화와 한 덩어리 | 기울기만 앞뒤 대칭 평활 | 떨림 295초 2.83 → 2.63, 420초 2.36 → 2.16 (원본 → 수평만) |

두 렌즈 각도의 측정: 다른 프레임 8곳에서 이음새 차이는 탐색값 18.82, 저장돼 있던 값 19.89, 파일 값 18.94입니다. 평균은 비슷하고 장면마다 다릅니다(12.4 대 17.8로 나은 곳, 29.8 대 23.6으로 못한 곳). 거리에 따른 시차 때문으로 보이며, 이 차이를 줄이는 것이 DJI의 프레임별 흐름 정렬입니다.

## Reelcut이 정한 값 (DJI 값이 아님)

| 값 | 내용 | 이유 |
|---|---|---|
| 수평 평활 σ 0.6초, 중앙값 ±0.1초 | `motion.rs` `LEVEL_SIGMA` | DJI 값은 VMProtect 안에 있음 |
| 흔들림 평활 σ = 세기 × 0.5초 | `motion.rs` `targets` | 같음 |
| 공장 값 채택 기준: 탐색값의 1.25배 이내 | `stitch.rs` | 탐색값은 같은 프레임에 맞춰져 유리하게 나옴 |
| 시간차 탐색 ±80ms, 1ms 단위 | `motion.rs` | 파일에 `offset` 값이 없음 |

## 아직 DJI와 다른 것

| 기능 | DJI | Reelcut | 상태 |
|---|---|---|---|
| 프레임별 이음새 정렬 | 신경망 흐름(모델 암호화), 실패 시 DIS 광학 흐름, 칼만·EMA | 블록 비교 + EMA. 기본은 꺼짐("정밀"에서만) | 미리보기에 없음. 셰이더로 옮기는 것은 남은 일 |
| 이음새 길찾기 | `FastHorizontalSeamFinder` | 동적 계획법 + 앞 프레임 연속성 | 구조는 같음. DJI 비용 값은 런타임 인수라 다 읽지 못함 |
| 색 맞춤 | 열마다 Y·Cr·Cb 이득, 시그모이드 유사도 | 파일당 한 번(기본), 64칸(정밀) | 비교만 함 |
| 섞기 | 겹침 가운데 50%(`len_ratio`), 두 대역 방식 있음 | 같은 비율, 선형만 | 두 대역 방식 없음 |
| 렌즈 온도 보정 | `temp_compen_k`, 프레임별 센서 온도 | 없음 | 계산식 미확인 |
| 거리별 렌즈 값 | `native_refine_far_*` | `native_refine`만 씀 | 선택 기준 미확인 |
| 롤링 셔터 | `EisGetCpuMesh…`, `DeRollingLevel` | 꺼짐 | 이 파일의 `sensor_readout_time`이 비어 있음 |
| 진행 방향 보기, 주인공 따라가기, 기울기 복원 | 각 `EisGetMatrixFor…` | 사람 따라가기만 자체 방식으로 있음 | 미구현 |
| 평활 시간 상수 | VMProtect 안 | 위 표 | DJI Studio로 내보낸 결과를 재면 맞출 수 있으나, 설치는 John의 허락이 필요함 |

재지 못한 것: DJI 결과와의 직접 비교, 이음새의 시간에 따른 깜빡임, 60fps 실제 영상.
